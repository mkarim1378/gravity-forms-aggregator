# Success Criteria — معیارهای موفقیت MVP

MVP **موفق** است اگر همه موارد زیر برقرار باشند:

## عملکردی

| # | معیار | قابل تست |
|---|-------|----------|
| 1 | مدیر بتواند چند فرم را با checkbox انتخاب کند | ✅ |
| 2 | بازه تاریخ (from/to) قابل تعیین باشد | ✅ |
| 3 | رفتار تاریخ خالی طبق spec باشد | ✅ |
| 4 | خروجی CSV سالم و قابل باز شدن در Excel/Sheets باشد | ✅ |
| 5 | خروجی Excel (XLSX) سالم دانلود شود | ✅ |
| 6 | داده‌ها مستقیماً از Gravity Forms خوانده شوند | ✅ |
| 7 | هیچ جدول/دیتابیس جدیدی ساخته نشود | ✅ |
| 8 | تعداد رکورد قبل از دانلود نمایش داده شود | ✅ |

## کیفیت

| # | معیار |
|---|-------|
| 9 | کار با ابزار سریع و ساده باشد (< 3 کلیک تا export) |
| 10 | ستون‌های خروجی مطابق [EXPORT-SPEC.md](EXPORT-SPEC.md) باشند |
| 11 | متن فارسی در CSV/Excel درست نمایش داده شود |
| 12 | فرم بدون entry در بازه — هشدار یا شمارش صفر |

## امنیت

|---|-------|

| 15 | ورودی‌های نامعتبر (form ID جعلی، تاریخ بد) رد شوند |

| 17 | کد قابل توسعه برای فازهای بعد باشد | architecture review |

## سناریوهای تست پذیرش

### سناریو 1: Export ساده

1. ورود به admin
2. انتخاب ۲ فرم
3. بدون تاریخ → export CSV
4. فایل شامل entryهای هر دو فرم با ستون‌های استاندارد

### سناریو 2: فیلتر تاریخ

1. انتخاب ۱ فرم
2. From = ۱۴۰۳/۰۱/۰۱، To = ۱۴۰۳/۰۶/۳۱
3. preview → تعداد صحیح
4. export Excel → فقط entryهای داخل بازه

### سناریو 3: فرم بدون داده

1. انتخاب فرمی که در بازه entry ندارد
2. preview → هشدار یا count = 0
3. export → فایل خالی با header یا پیام مناسب

### سناریو 4: دسترسی

1. کاربر بدون `manage_options` → 403 / redirect
2. درخواست export بدون nonce → رد

## Definition of Done (هر فاز)

- [ ] کد review شده
- [ ] تست دستی سناریوهای مرتبط
- [ ] مستندات به‌روز (در صورت تغییر spec)
- [ ] بدون regression امنیتی
