# PRD — Product Requirements Document

## 1. هدف محصول

ساخت یک ابزار مدیریتی برای سایت وردپرسی که بتواند:

- فرم‌های Gravity Forms را لیست کند
- به مدیر اجازه دهد فرم‌های موردنظر را با تیک انتخاب کند
- بازه زمانی برای اکسپورت تعیین کند
- ورودی‌های فرم‌های انتخاب‌شده را از دیتابیس بخواند
- خروجی تجمیعی در قالب CSV و Excel تولید کند
- در نسخه‌های بعدی، فرم‌های قدیمی و فعال را بهتر رصد کند

## 2. مسئله اصلی

در طول زمان تعداد فرم‌های Gravity Forms زیاد شده و بررسی دستی آن‌ها سخت شده است.

### مشکلات فعلی

| مشکل | توضیح |
|------|-------|
| فرم‌های قدیمی فعال | فرم‌های قدیمی هنوز ورودی می‌گیرند و کسی متوجه نمی‌شود |
| از دست رفتن داده | داده‌ها از دست می‌روند یا پراکنده می‌مانند |
| اکسپورت دستی | گرفتن خروجی برای چند فرم به‌صورت هم‌زمان وقت‌گیر است |

## 3. کاربر هدف

- مدیر سایت (Administrator)
- ادمین‌های تعریف‌شده
- در آینده: نقش‌های سفارشی مثل `forms_manager`

## 4. راه‌حل پیشنهادی

یک افزونه وردپرس اختصاصی که:

1. فرم‌ها را از Gravity Forms می‌خواند
2. روی درخواست کاربر کوئری می‌زند
3. فایل خروجی را همان لحظه تولید می‌کند

### مزایا

- سبک و سریع
- کم‌هزینه
- بدون مهاجرت داده
- مناسب MVP

### ریسک‌ها

| ریسک | راهکار |
|------|--------|
| حجم داده زیاد | pagination / batching |
| محدودیت زمان PHP | chunked export، بهینه‌سازی کوئری |
| مصرف حافظه در Excel | کتابخانه memory-friendly |

## 5. پیشنهاد نهایی MVP

| شامل | خارج از scope |
|------|---------------|
| صفحه مدیریت فرم‌ها | داشبورد تحلیلی |
| لیست فرم‌ها با checkbox | اعلان ایمیلی/تلگرامی |
| فیلتر from/to | امتیازدهی ریسک |
| خروجی CSV | ساخت دیتابیس جدید |
| خروجی Excel | deduplication پیشرفته |
| بدون دیتابیس جدید | تاریخچه بررسی فرم‌ها |
| کوئری مستقیم به GF | نقش‌های دسترسی پیچیده |

## 6. نسخه بعدی

- هشدار فرم‌های قدیمی که هنوز ورودی می‌گیرند
- گزارش فرم‌های فعال
- اعلان‌ها
- ذخیره preset
- گزارش‌های ماهانه
