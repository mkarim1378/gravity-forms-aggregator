# Design Principles — اصول طراحی

## اصل 1: حداقل وابستگی

ابزار باید تا حد امکان فقط به موارد زیر وابسته باشد:

- WordPress
- Gravity Forms
- دیتابیس فعلی

از وابستگی به سرویس‌های خارجی، API ثالث یا زیرساخت اضافی پرهیز شود.

## اصل 2: عدم ایجاد پیچیدگی غیرضروری

اگر با کوئری مستقیم به جداول Gravity Forms نیاز حل می‌شود، **فعلاً** ساختار جدیدی برای ذخیره‌سازی ساخته نمی‌شود.

- داده فقط خوانده می‌شود
- خروجی در لحظه تولید می‌شود
- هیچ جدول جدیدی در MVP ایجاد نمی‌شود

## اصل 3: قابل توسعه بودن

حتی اگر MVP سبک باشد، ساختار کد باید طوری باشد که بعداً بتوان اضافه کرد:

- گزارش‌ها
- هشدارها
- فیلترهای بیشتر
- خروجی‌های بیشتر (JSON، PDF و …)
- preset‌های ذخیره‌شده
- نقش‌های دسترسی سفارشی

### پیاده‌سازی پیشنهادی

```
┌─────────────────────────────────────┐
│           Admin UI Layer            │
├─────────────────────────────────────┤
│         Export Controller           │
├──────────────┬──────────────────────┤
│  Data Layer  │   Export Layer       │
│  (GF Query)  │  (CSV / Excel)       │
└──────────────┴──────────────────────┘
```

لایه‌ها از هم جدا باشند تا افزودن فرمت یا فیلتر جدید بدون بازنویسی کل سیستم ممکن شود.

## اصل 4: امنیت پیش‌فرض

دسترسی محدود به نقش‌های مجاز، nonce، sanitization و validation از ابتدا در نظر گرفته شود — نه به‌عنوان افزودنی بعدی.

## اصل 5: شفافیت برای کاربر

قبل از دانلود، کاربر باید بداند:

- چند فرم انتخاب شده
- چند رکورد پیدا شده
- بازه تاریخ چیست
- کدام فرم‌ها داده ندارند
